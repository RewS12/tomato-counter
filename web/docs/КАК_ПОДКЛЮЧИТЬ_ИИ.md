# Как подключить ИИ к AgroVision и улучшить качество работы

## 1. Текущее состояние (не нейросеть)

Сейчас `POST /apiv2/analyze/fruits` применяет **OpenCV HSV**: цветовые маски, морфология, контуры, геометрическая фильтрация и подсчёт. Для сложных изображений, особенно для зелёных плодов на фоне листьев, метод даёт ложные пропуски и слияния объектов. Модуль почвы и листьев оценивает только простые визуальные показатели и не ставит диагноз. Проверка 10+3 проведена на **синтетике**, не на реальных теплицах.

## 2. Архитектура ИИ: что внедрять первым

Приоритет №1 — обученный **детектор отдельных томатов** на реальных фото. Пример: специализированная YOLO-модель с одним классом `tomato`, тогда зрелость классифицируется отдельно по видимой области. Альтернатива — два класса `ripe_tomato` и `unripe_tomato`, но пограничные стадии требуют согласованных правил разметки. Если нужен точный цвет объекта при перекрытиях и листве, следующая ступень — **instance segmentation**, потому что прямоугольная рамка захватывает фон.

Рекомендуемый конвейер:

`Фото → проверка и нормализация → детектор томатов → bounding boxes/маски → оценка видимого цвета в маске → категории красный / зелёный / неопределённый → ручная верификация → SQLite/дневник`.

Не подключайте общую языковую модель для подсчёта — она не гарантирует координаты каждого плода и воспроизводимое число объектов. LLM может объяснять уже проверенные результаты и вести справочник, но не должна генерировать отсутствующие измерения.

## 3. Набор данных и разметка

1. Соберите изображения томатов разных сортов и стадий, при разных ракурсах, освещении и камерах. Включите сложные случаи: зелёные плоды, листья, перекрытия, блики, тени и пустые фото. Получите права на изображения.
2. Разметьте **каждый видимый плод** прямоугольником, включая частично закрытые (пометка по видимой части или согласованному правилу). Для зрелости используйте единый регламент; неоднозначные объекты помечайте отдельно.
3. Не размещайте соседние кадры одного куста в разных split: разделение делайте **по теплице, растению, дате или фотосессии**, чтобы почти дублированные снимки не завышали оценку.
4. Разделите на train / validation / test, например 70 / 15 / 15% *как отправную точку, не обязательный норматив*. Test отложите до финальной проверки порогов и архитектуры.
5. Можно использовать CVAT для разметки с экспортом YOLO, но проверяйте соответствие формата и class IDs используемому обучающему пайплайну.

Пример файла `dataset.yaml` для модели с одним классом:

```yaml
path: /absolute/path/to/tomato_dataset
train: images/train
val: images/val
test: images/test
names:
  0: tomato
```

Структура разметки: `images/train/xxx.jpg` и `labels/train/xxx.txt`. В каждой строке TXT: `class_id center_x center_y width height`, координаты нормированы от 0 до 1. Контрольные фотографии проекта из `data/validation` синтетические; их нельзя использовать как доказательство качества новой модели на реальных теплицах.

## 4. Подключение весов к готовому сайту

В сборку включён адаптер `backend/yolo_adapter.py`. **Он не является обученной моделью и без `.pt` работать не будет**. Требуются совместимые права на использование Ultralytics и собственные специализированные веса.

### Локальный запуск

```bash
python -m pip install -r requirements-ai.txt
# Поместите обученные веса в models/tomato_best.pt
# Linux/macOS:
export AGROVISION_DETECTOR=yolo
export AGROVISION_YOLO_WEIGHTS=models/tomato_best.pt
python -m uvicorn backend.main:app --host 127.0.0.1 --port 8000
```

Windows PowerShell:

```powershell
$env:AGROVISION_DETECTOR="yolo"
$env:AGROVISION_YOLO_WEIGHTS="models/tomato_best.pt"
python -m uvicorn backend.main:app --host 127.0.0.1 --port 8000
```

### Docker

Сохраните `models/tomato_best.pt` в каталоге проекта, затем в `.env` установите:

```ini
AGROVISION_INSTALL_AI=true
AGROVISION_DETECTOR=yolo
AGROVISION_YOLO_WEIGHTS=models/tomato_best.pt
AGROVISION_YOLO_CONF=0.30
```

Далее `docker compose up -d --build`. Без весов **оставьте OpenCV**, иначе `/apiv2/analyze/fruits` вернёт понятную ошибку 503. Если модель классифицирует `ripe_tomato` / `unripe_tomato`, адаптер использует эти имена; при единственном классе `tomato` применяет цветовой анализ внутри центральной части рамки. Этот цветовой анализ остаётся эвристическим и должен быть заменён масками/обученной оценкой в сложной теплице. `detector_score` — оценка модели для детекции объекта, **не вероятность зрелости и не калиброванная надёжность**.

## 5. Как обучать

После подготовки настоящей разметки и установки `ultralytics` обучите на совместимой исходной модели согласно документации конкретной версии. Схематичный пример:

```python
from ultralytics import YOLO
model = YOLO("path/to/compatible_pretrained_detector.pt")
model.train(data="dataset.yaml", epochs=80, imgsz=768, project="runs/tomatoes")
metrics = model.val(data="dataset.yaml", split="test")
```

Выбор числа эпох и разрешения — **пример**, а не гарантированные оптимальные настройки; подбирайте по loss-кривым, данным и аппаратным ресурсам. Перенесите итоговый файл весов из runs в `models/tomato_best.pt`. Не используйте стандартные COCO-веса как якобы обученные на томатах: в COCO нет обязательного класса tomato.

## 6. Что действительно повысит качество

**Сначала данные, затем модель.** Добавьте сложные реальные фотографии, корректно разметьте сливающиеся и зелёные плоды, учитывайте разные камеры. Не оценивайте качество на тех же кустах, на которых обучали. Добавьте instance segmentation и классификацию внутри маски. Контролируйте баланс классов, используйте умеренные аугментации яркости/цвета без изменения смысла метки, hard-negative примеры листьев/помидороподобных объектов, ручную корректировку ошибок и повторное обучение.

Практическая метрика: precision, recall и F1 детекции по IoU 0.5 и отдельно mAP50–95; MAE количества на фото и по грядкам; confusion matrix категорий; доля неопределённых; p50/p95 latency; сравнение по реальным условиям (тень, зелёные плоды, бликующие плоды, частичные перекрытия). Проверяйте калибровку вероятностей, если на UI нужна «уверенность». До калибровки показывайте только raw model score.

**Пример критерия пилота, подлежащего согласованию:** MAE не более 1 плода на фото при данном фотопротоколе и >0.9 recall по видимым плодам на независимой контрольной выборке. Это не достигнутые цифры и не гарантия; реальные цели зафиксируйте с заказчиком после замеров.

## 7. Рекомендации, листья, почва: отдельные модули

Для листьев нужны специализированные фотографии и отдельный классификатор/сегментация видимых симптомов, агрономическая верификация; для почвы RGB-фото не измеряет NPK, pH или влагу корней. Подключайте реальные датчики влажности/температуры и журнал полива, затем правила принятия решений. Сервис не должен автоматически назначать пестициды и дозировки по одному снимку.

LLM можно добавить **позже** как текстовый помощник поверх структурированных наблюдений. Передавайте в него список объектов, дневник и проверенные справочные материалы, требуйте ссылки на конкретные источники знаний и явное указание неопределённости; запрещайте ему переписывать счётчики и создавать агрономические диагнозы без подтверждения.

## 8. Эксплуатация и безопасность

Не отправляйте пользовательские фото во внешние модели без согласия и правового основания. Данные находятся на вашем сервере в SQLite и `runtime/images`; для коммерческого сервиса потребуются аккаунты, разделение хозяйств, резервные копии, TLS и наблюдаемость. При поставке Ultralytics учитывайте **AGPL-3.0** и необходимость отдельной Enterprise-лицензии для некоторых закрытых коммерческих сценариев. Изучите условия используемых весов и изображений.
