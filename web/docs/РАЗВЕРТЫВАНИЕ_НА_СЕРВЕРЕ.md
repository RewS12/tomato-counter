# AgroVision: серверное развёртывание

## 1. Что находится в архиве

Серверные файлы: `backend/`, `frontend/`, `data/`, `models/`, `runtime/`, `requirements.txt`, `requirements-ai.txt`, `Dockerfile`, `docker-compose.yml`, `docker-compose.public.yml`, `deploy/Caddyfile`, `.env.server.example`, `README.md`, `docs/` и `presentation/`.

Фронтенд содержит собственные локальные SVG-иконки, иконку сайта, PWA-иконки PNG 192/512/180, CSS, JavaScript и локальную фотографию томатов. Синтетические тестовые изображения также лежат в архиве. Веб-приложение **не использует CDN, внешние JS/CSS, веб-шрифты или платные внешние API**. Для единообразия выбран системный шрифт. Python-пакеты и базовый образ Docker при первом развёртывании загружаются из официальных репозиториев.

**Не открывайте `frontend/index.html` двойным щелчком:** он содержит серверные пути `/static`, `/api` и `/samples`.

## 2. Вариант A. Docker на VPS/Linux (рекомендуется для сервера)

Требуются Docker Engine с плагином Docker Compose v2, свободное место для образа и снимков, доступ к Интернету для первой сборки.

```bash
# Выполнить из корня распакованного проекта AgroVision_СЕРВЕР
cp .env.server.example .env
# Откройте .env и замените AGROVISION_BASIC_PASSWORD
# на уникальный случайный пароль длиной не менее 12 символов.
docker compose up -d --build
docker compose ps
docker compose logs --tail=100 agrovision
curl http://127.0.0.1:8000/apiv2/health
```

Сервер прослушивает только `127.0.0.1:8000` на VPS; открывать этот HTTP-порт всему Интернету **не нужно**. Откройте веб-сайт на самом сервере `http://127.0.0.1:8000`. Для работы со своего компьютера используйте SSH-туннель:

```bash
ssh -L 8000:127.0.0.1:8000 user@YOUR_SERVER
```

После входа откройте на собственном компьютере `http://127.0.0.1:8000`, введите Basic-логин и пароль из `.env`. Браузер запоминает Basic-доступ на время сеанса, поэтому не используйте этот режим на общем компьютере.

## 3. Вариант B. Публичный домен по HTTPS

Нужны: домен с DNS A/AAAA на VPS, разрешённые входящие порты 80 и 443, сильный пароль. В `.env` установите `AGROVISION_DOMAIN=agro.example.com` (ваше настоящее доменное имя). Затем:

```bash
docker compose -f docker-compose.yml -f docker-compose.public.yml up -d --build
```

Caddy автоматически запрашивает и обновляет сертификат HTTPS и проксирует запросы в FastAPI. **Проверяйте `https://ваш-домен/`, не отправляйте Basic-пароль через обычный HTTP.** Пароль защищает только один демонстрационный доступ, это не аккаунты и не разграничение ролей. Для большого числа пользователей потребуются SSO/OIDC, роли, лимиты запросов, журнал доступа, политика хранения и резервного копирования.

После запуска проверьте `/`, `/app`, `/apiv2/health`, `/static/css/style.css`, `/static/assets/icon.svg`, `/static/assets/icon-192.png`, `/samples/demo/tomato_01.jpg`. Лендинг, статика и демо-примеры публичны; `/app`, `/apiv2/*`, `/media/*` и `/docs` требуют Basic-аутентификации, включая `/apiv2/health`.

## 4. Обновление и резервное копирование

Данные хранятся в именованном Docker volume `agrovision_data`: SQLite (`/app/runtime/agrovision.sqlite3`) и загруженные изображения (`/app/runtime/images`). Для резервной копии желательно остановить запись, затем сохранить данные:

```bash
docker compose stop agrovision
docker run --rm -v agrovision_agrovision_data:/data -v "$PWD":/backup alpine sh -c 'cd /data && tar czf /backup/agrovision-data-backup.tgz .'
docker compose start agrovision
```

Имя Docker volume зависит от имени каталога/проекта — уточните его через `docker volume ls`. Переименовывание папки может создать новый volume. `docker compose down` обычно оставляет данные, а `docker compose down -v` **удаляет** их. Регулярно тестируйте восстановление копии.

Для обновления файлов загрузите новую версию, сохраните `.env`, затем `docker compose up -d --build`. Перед миграциями БД делайте backup.

## 5. Вариант без Docker (для локальной машины, не для публичного сервера)

```bash
python -m venv .venv
# Linux/macOS:
. .venv/bin/activate
# Windows: .venv\Scripts\activate
python -m pip install -r requirements.txt
python -m uvicorn backend.main:app --host 127.0.0.1 --port 8000
```

Адрес: `http://127.0.0.1:8000` и приложение `http://127.0.0.1:8000/app`.

## 6. Диагностика проблем

- **Ничего не открывается:** `docker compose ps`, `docker compose logs agrovision`, проверка порта, файла `.env` и пароля.
- **401 Unauthorized:** пароль или логин неверны. При изменении Basic-реквизитов перезапустите браузер/откройте приватное окно.
- **502 через домен:** контейнер приложения не прошёл health-check или Caddy не может связаться с ним.
- **Сайт есть, но изображения пропали:** проверьте пути `/static/...` и `/media/...`, права доступа и том данных.
- **Анализ не выполняется:** проверьте файл JPG/PNG/WebP до 8 МБ, логи сервера, CV-режим `AGROVISION_DETECTOR=opencv`.
- **Включили YOLO и получили 503:** специализированных весов нет в `models/`, не установлен `ultralytics` или классы не соответствуют томатам. Верните `AGROVISION_DETECTOR=opencv` до завершения обучения.
- **После обновления старый CSS:** обновите страницу без кэша и очистите storage/service worker в DevTools, если требуется.

## 7. Ограничения безопасности

Это демонстрационный одноинстансовый сервис с Basic-доступом и SQLite. Для коммерческой эксплуатации нужны защита от CSRF, управление пользователями, политика удаления фотографий, ограничения частоты обращений, журналирование доступа, хранение секретов и тестирование безопасности. Публичный домен с Basic-доступом следует использовать только для закрытого показа небольшой группе.
