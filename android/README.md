# android/ — Kotlin-клиент «Томаты»

Камера или галерея → фото уходит на сервер (`POST /detect`) → рамки на фото + сводка «всего / зрелых / незрелых».
Модель работает на ноутбуке ([ADR-002](../brain/05_Решения_ADR/ADR-002%20On-device%20или%20сервер.md)), приложение — тонкий клиент.

## Сборка
```bash
./gradlew assembleDebug          # → app/build/outputs/apk/debug/app-debug.apk
./gradlew installDebug           # сразу на телефон по USB (включить отладку по USB)
```
- ADB без Android Studio: `../tools/platform-tools/adb.exe` (скачивается локально, демон уже запущен).
- По Wi-Fi: включить «Отладка по Wi-Fi» на телефоне, затем `adb pair <IP>:<порт>`, ввести код и `adb connect <IP>:<порт>`.
- `./gradlew installDebug` работает и на подключённом по Wi-Fi устройстве.
- Нужны Android SDK (API 36) и JDK 17+ (подойдёт `jbr` из Android Studio: `JAVA_HOME="C:/Program Files/Android/Android Studio/jbr"`).
- `local.properties` — путь к SDK, через **прямые слэши**: `sdk.dir=C:/Users/<имя>/AppData/Local/Android/Sdk` (обратные слэши ломают сборку). В этом проекте SDK поставлен локально в `tools/android-sdk`.
- В пути проекта кириллица → в `gradle.properties` стоит `android.overridePathCheck=true`.
- Стек: AGP 9.1 (встроенный Kotlin), Gradle 9.3.1, minSdk 26 (Android 8), Material 3 (View system), без Compose.

## Использование
1. Бэкенд: `cd server && docker compose up -d --build` (публичный адрес — `https://agro.setly.space/android-api`).
2. Телефон и ноутбук — в одной сети (для локального IP; надёжнее всего: хот-спот с телефона).
3. Адрес уже подставлен — `https://agro.setly.space/android-api`. Изменить его можно на вкладке **«Сервер»**; для локальной сети введите IP ноутбука (`ipconfig` → IPv4) — `http://` и `:8002` добавятся сами. **Проверить** → «Сервер OK».
4. **📷 Снять** или **🖼 Галерея** → рамки: красная = зрелый, зелёная = незрелый, число = уверенность.
5. Вкладка **«Видео»** — потоковая детекция: стрим запускается автоматически при открытии вкладки, кадры уходят на сервер по WebSocket (`/ws/stream`). На экране — LIVE-бейдж с моделью, устройством (`cuda`/`cpu`) и временем кадра, рамки и счётчики в реальном времени. **Остановить / Запустить** — ручное управление; при уходе с вкладки стрим останавливается.

## Как устроено
| Файл | Что |
|---|---|
| `MainActivity.kt` | экран анализа, вкладки «Сервер» и «О проекте», камера (системное приложение), фотопикер, сохранение адреса |
| `DetectApi.kt` | HTTP: `/health`, `/detect` (multipart), понятные тексты ошибок сети |
| `LiveStreamClient.kt` | WebSocket-клиент: кадр → JSON с детекцией, конвертация `http(s)` → `ws(s)` |
| `StreamView.kt` | canvas-оверлей поверх превью камеры: рамки, счётчики, LIVE-бейдж |
| `ImageUtils.kt` | поворот по EXIF, уменьшение до 1280 px, JPEG, отрисовка рамок |

В live-режиме используется CameraX `ImageAnalysis` (640×480, `KEEP_ONLY_LATEST`) и JPEG quality 60. Одновременно в полёте только один кадр; запоздавшие callbacks старого WebSocket игнорируются через `liveGeneration`.

Фото поворачивается по EXIF **на телефоне** и уходит без EXIF — поэтому координаты боксов от сервера совпадают с картинкой на экране.
HTTP без TLS разрешён (`usesCleartextTraffic`) — сервер в локальной сети. Экран зафиксирован в портретной ориентации.

## Если не работает
| Симптом | Что делать |
|---|---|
| «Нет связи с сервером» | сервер с `--host 0.0.0.0`? одна сеть? IP актуальный? |
| «Сервер не ответил вовремя» | брандмауэр Windows: разрешить Python в частной сети или открыть порт 8000 |
| Рамки смещены | сообщить — значит, где-то потерялся EXIF-поворот |
| «Соединение закрыто» на вкладке «Видео» | проверить `https://agro.setly.space/android-api/health`; VPN/сеть телефона; сервер должен быть поднят с GPU для ~20–30 мс/кадр |
