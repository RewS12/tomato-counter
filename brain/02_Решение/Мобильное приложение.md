# Мобильное приложение (APK)

## Минимальный функционал
1. Кнопка «Сфотографировать» и **«Выбрать из галереи»** (галерея обязательна — сценарий ТЗ = загрузка фото).
2. Экран результата: фото с рамками (цвет = категория), сводка «Всего N · зрелых X · незрелых Y».
3. Сохранение результата (картинка + JSON) — пригодится для сравнения по датам.

## Варианты технологий
| | Скорость разработки | On-device ML | Комментарий |
|---|---|---|---|
| Kotlin + CameraX | средняя | TFLite / NCNN | нативно, если есть Android-разработчик |
| Flutter | средняя | tflite_flutter | один код, но плагины капризные |
| WebView/PWA + сервер | высокая | нет | APK-обёртка над веб-страницей, камера через браузер |
| Готовый Ultralytics/NCNN Android-пример | высокая для on-device | да | форкнуть и заменить веса |

✅ Выбрано: **Kotlin**, тонкий клиент к серверу ([[ADR-002 On-device или сервер]]). Поле для IP сервера в настройках.

## Нюансы
- Live-режим (рамки поверх видеопотока) — **бонус**, не базовый режим. Сначала «снял → получил результат».
- Ориентация/EXIF-поворот фото — классический баг, проверить сразу.

## ✅ Реализовано (2026-10-16) — `android/`
- Kotlin, AGP 9.1 / Gradle 9.3.1, minSdk 26, без Compose, зависимости — только androidx + coroutines.
- Поле адреса (запоминается) + «Проверить» (`/health`); «📷 Снять» (системная камера через FileProvider) и «🖼 Галерея» (фотопикер, без разрешений).
- Фото поворачивается по EXIF и уменьшается до 1280 px **на телефоне** → координаты боксов от сервера совпадают с экраном.
- Рамки: красная = ripe, зелёная = unripe, подпись — уверенность в %. Сводка крупно сверху.
- Понятные ошибки сети («одна сеть? --host 0.0.0.0? брандмауэр?»).
- APK собран (2.8 МБ, debug). **На реальном телефоне ещё не проверен.**

### Грабли при сборке
- Кириллица в пути проекта → `android.overridePathCheck=true` в `gradle.properties` (с ним собирается).
- `local.properties`: путь к SDK только с прямыми слэшами — обратные дают «Invalid file path».
