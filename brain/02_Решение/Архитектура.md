# Архитектура

## Предлагаемая схема (гибрид, «ядро отдельно от оболочки»)

```
[Камера / Галерея]  ──►  Android APK (тонкий клиент)
                              │  фото (JPEG)
                              ▼
                 ┌─────────────────────────────┐
                 │ ЯДРО (Python)                │
                 │ 1. детектор плодов (YOLO)    │
                 │ 2. зрелость: класс или HSV   │
                 │ 3. подсчёт + отрисовка       │
                 └─────────────────────────────┘
                              │ JSON: боксы, классы, счётчики
                              ▼
                 APK рисует рамки + сводку
```

Ядро — на сервере, см. [[ADR-002 On-device или сервер]] (принято).
- **A. Сервер** (ноутбук в той же Wi-Fi / FastAPI): быстро делать, легко менять модель. Риск — сеть на площадке.
- **B. On-device** (YOLO → TFLite/NCNN в APK): автономно, вау. Риск — Android-сборка съест день.
- **C. Гибрид:** сначала A, затем, если время останется, — B.

## Почему ядро отдельно
- Одна и та же функция `detect(image) -> results` используется в APK, в скрипте оценки точности ([[Протокол оценки точности]]) и в запасном веб-интерфейсе.
- Если APK сломается на демо — показываем то же самое через запасной UI (Streamlit/Gradio). См. [[Риски]].

## Контракт API (реализован 2026-10-16)
Код: `server/app/` · подробности: `server/README.md`
- `POST /detect` (multipart, поле `image`, `?draw=true` → JPEG с разметкой в `image_b64`)
- `GET /health` — пинг для поля IP в APK
- `GET /` — запасной веб-интерфейс (камера через браузер телефона)

```json
{"total": 2, "counts": {"ripe": 1, "unripe": 1},
 "objects": [{"bbox": [x1,y1,x2,y2], "cls": "ripe", "conf": 0.59, "label": "apple", "red_ratio": 0.82}],
 "width": 800, "height": 1118, "model": "yolo11n.pt", "mode": "stub", "ms": 170}
```
- `bbox` — в пикселях фото после EXIF-поворота.
- `mode`: `stub` (COCO apple/orange + HSV) → `trained` (наша модель, включается автоматически по именам классов).
